Bot Gateway store - change log
Changes of the repository itself: the app kit (kit/), the store tools (tools/), README, LICENSE.
The top section is the store's coming version (no date): write each change below it as "- ...";
store_update.sh --store publishes it (dated; the version is in the signed store.json and shown in the
Portal) and puts the next patch version on top. Package changes go into packages/<id>/CHANGELOG.TXT.

- [Changed and non commited item put here]

1.0.5 (2026-11-01)
- App kit tags: every tag is listed under the search as a chip (most used first) - click one to filter, click it
  again or "All" to show everything (replaces the tag menu); a tag on an item's page opens the list filtered
  by it

1.0.4 (2026-11-01)
- App kit: field type `tags` - several short labels per item (at most 20 × 30 characters; "a, b、c" is split;
  the same tag once). The list can be filtered by a tag and lists the tags there are (most used first; for
  visitors only those of published items); the page shows them as # chips, has a tag menu next to the search,
  and the form suggests the existing tags to click

1.0.3 (2026-10-31)
- App kit: "Can't reach this application" also tells the owner what to do after BotGateway was restarted (open
  the application again from the BotGateway app)

1.0.2 (2026-10-31)
- App kit: triggers - createApp({ onHook(name, req, hook) }) takes webhooks from outside services at
  https://<website>/hook/<name> (gateway 1.0.2 or later); without onHook an application has none (404).
  hook: name, header(), text, json(), signature(secret) (HMAC of the exact body), same() (constant-time),
  seen(id) (de-duplicates event ids for 7 days), op(), get(), reply()

1.0.1 (2026-10-30)
- App kit: a collection's `years` ("updated" / "created") - the list can be filtered by year (the page gets a
  year menu next to the search; the list's answer names the years there are, visitors only published ones)
- App kit: 👁 Preview on an item's page (owner, collections visitors may read) shows it exactly as the website
  does, with a note (and whether it is published yet) and the way back; meta says which actions are public
- README, STORE_CHANGELOG / CHANGELOG headers and build_store.py name store_update.sh (was update_store.sh)

1.0.0 (2026-10-30)
- Change logs: STORE_CHANGELOG.TXT and packages/<id>/CHANGELOG.TXT (not packed); build_store.py puts each
  version's changes into store.json ("What's new" in the Portal and the gateway) and takes --only <id>
- README: change logs and how to publish
- The store has a version (this file's newest released one), shown in the Portal after "Package Store"
